Names point at objects

A variable in Python is a name tag stuck on an object, not a box that holds a value. b = a puts a second tag on the same object. For a mutable object (list, dict, set) that means a change made through one name is visible through the other — and tests that share a "default payload" dict leak state into each other.

Interactive — one payload, two names

The same three behaviours in real Python:

import copy

a = [1, 2]
b = a                     # same list, two names
b.append(3)
print(a)                  # [1, 2, 3]   <- a changed too!

base = {"firstname": "Ada", "bookingdates": {"checkin": "2026-01-01"}}
shallow = dict(base)                      # outer dict copied, nested dict SHARED
shallow["bookingdates"]["checkin"] = "2026-02-02"
print(base["bookingdates"])               # {'checkin': '2026-02-02'}   <- leaked into base

deep = copy.deepcopy(base)                # everything copied, recursively
deep["bookingdates"]["checkin"] = "2026-03-03"
print(base["bookingdates"])               # still 2026-02-02 - base is safe this time
⚠ Why QE cares "Passes alone, fails in the suite" is very often shared mutable data. Copy first (dict(payload), copy.deepcopy) or — better — build fresh data per test with a factory function.

Numbers that are money

A float is a binary approximation: most decimal fractions cannot be stored exactly, so totals drift by fractions of a cent and equality assertions fail. Decimal, built from a string, stores exactly what you typed.

int — exact, any size float — fast, approximate Decimal("29.99") — exact decimal, for prices and totals quantize + ROUND_HALF_UP — rounding as a stated business rule 
from decimal import Decimal, ROUND_HALF_UP

print(0.1 + 0.2)                          # 0.30000000000000004
print(Decimal("0.1") + Decimal("0.2"))    # 0.3
print(Decimal(2.675))                     # what the float 2.675 REALLY holds
print(round(2.5), round(3.5))             # 2 4   - banker's rounding (half to even)
print(round(2.675, 2))                    # 2.67  - because of the line above
print(Decimal("2.675").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))   # 2.68
⚠ Gotchas 1. Decimal(29.99) (from a float) inherits the float's error — always Decimal("29.99"). 2. round(2.5) == 2: Python rounds half to even (banker's rounding). 3. A one-cent mismatch between your expected value and the product is a real bug class — confirm which rounding rule the product uses.

deep dive Four things that separate a pass from a strong answer

🔵 Medium: sort, group and find duplicates. The dropdown's four modes become a dict of (key, reverse) pairs.

from collections import Counter, defaultdict

def sort_products(products, mode: str):
    keys = {
        "az":   (lambda p: p["name"], False),
        "za":   (lambda p: p["name"], True),
        "lohi": (lambda p: p["price"], False),
        "hilo": (lambda p: p["price"], True),
    }
    key, reverse = keys[mode]            # KeyError for unknown mode = fail fast
    return sorted(products, key=key, reverse=reverse)

def names_by_price(products):
    grouped = defaultdict(list)
    for p in products:
        grouped[p["price"]].append(p["name"])
    return dict(grouped)

def duplicate_prices(products):
    counts = Counter(p["price"] for p in products)
    return {price for price, n in counts.items() if n > 1}

assert sort_products(PRODUCTS, "lohi")[0]["name"] == "Sauce Labs Onesie"
assert duplicate_prices(PRODUCTS) == {Decimal("15.99")}
Sort O(n log n)Group / count O(n)Space O(n)
Hire signal"A dict lookup replaces an if/elif ladder, and an unknown mode raises KeyError straight away — fail fast. defaultdict and Counter group and count in a single pass."
Level 3 — Hero Mode

🟣 High/Complex: property-based sort check with diagnostics (reused in P05). Don't just say "not sorted" — say where.

def is_sorted(values, reverse: bool = False) -> bool:
    return all((a >= b) if reverse else (a <= b) for a, b in zip(values, values[1:]))

def first_unsorted_pair(values, reverse: bool = False):
    """Return (index, left, right) of the first violation, or None. Great for assertion messages."""
    for i, (a, b) in enumerate(zip(values, values[1:])):
        if (a < b) if reverse else (a > b):
            return i, a, b
    return None

ui_prices = [Decimal("7.99"), Decimal("15.99"), Decimal("9.99")]   # e.g. what problem_user shows
assert not is_sorted(ui_prices)
assert first_unsorted_pair(ui_prices) == (1, Decimal("15.99"), Decimal("9.99"))
Time O(n)Space O(n) for the slicestops at the first violation
Why it's hero-levelzip(values, values[1:]) pairs each element with its neighbour — an idiom worth memorising. first_unsorted_pair returns the index and both values: exactly what a useful assertion message needs.

Interview Q&A

Answer out loud in under two minutes before you open each one.

ZList vs tuple?
Both are ordered sequences. Lists are mutable and tuples are immutable. Use tuples for fixed records (e.g. ("standard_user", "secret_sauce") in parametrize) and as dict keys, since they're hashable if their contents are. Use lists for collections that grow or change.
ZAre dicts ordered in Python?
Yes. Since Python 3.7, dicts preserve insertion order as a language guarantee. Don't rely on JSON API responses keeping key order for equality checks, though. Compare dicts, not strings.
HWhy is x in my_set faster than x in my_list?
Sets and dicts are hash tables: membership hashes x and jumps to its bucket, O(1) on average. Lists scan every element, O(n). With 10k IDs to reconcile, that's the difference between milliseconds and seconds. Set operations (-, &, |) also express "missing/extra records" clearly.
HShallow vs deep copy? Give a testing example.
A shallow copy (dict(d), list(l), copy.copy) copies the outer container but shares nested objects. A deep copy (copy.deepcopy) copies everything recursively. Example: a base booking payload with nested bookingdates. Shallow-copying it and changing bookingdates["checkin"] mutates the base for every other test. Use deepcopy or a factory function that builds fresh data.
HWhy shouldn't you use float for prices?
Binary floats can't represent most decimals exactly (0.1 + 0.2 != 0.3), so totals drift by fractions of a cent and equality assertions fail. Use Decimal constructed from strings, and apply explicit rounding rules (quantize with ROUND_HALF_UP) that match the business requirement.

deep dive The mutable default trap — a top interview question

Defaults are evaluated once, when the function is defined. A default [] is one list shared by every call. Use cart: list | None = None and create the list inside.

def add_item(item, cart=[]):          # the SAME list is reused across calls
    cart.append(item)
    return cart

print(add_item("Backpack"))           # ['Backpack']
print(add_item("Onesie"))             # ['Backpack', 'Onesie']   <- state leaked between calls!

def add_item_fixed(item, cart: list | None = None):
    if cart is None:
        cart = []                     # a fresh list on every call
    cart.append(item)
    return cart

print(add_item_fixed("Backpack"))     # ['Backpack']
print(add_item_fixed("Onesie"))       # ['Onesie']
deep dive Rounding is a business rule

Python's round(2.5) == 2 uses banker's rounding (round half to even), and round(2.675, 2) == 2.67 because 2.675 is really 2.67499999… as a float. For money use Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP) and confirm which rule the product uses. A one-cent mismatch is a real bug class.

deep dive Exceptions as a design tool

Raise specific exceptions (CheckoutValidationError) rather than returning False or error strings. Callers can't accidentally ignore them, and pytest can assert them with pytest.raises(..., match=...). Catch narrowly: except KeyError, never bare except:, which also swallows KeyboardInterrupt and hides bugs. Use raise ... from e to keep the original cause in the traceback.

deep dive try / except / else / finally — the order

try runs; except handles failures; else runs only if there was no exception; finally always runs, which makes it the place for cleanup like closing a browser or deleting test data.

🔵 Medium: money maths plus a custom exception. The whole of task steps 1 and 2 in twenty lines.

from decimal import Decimal, ROUND_HALF_UP

CENT = Decimal("0.01")

class CheckoutValidationError(ValueError):
    """Raised when checkout info is invalid; message mirrors the UI."""

def calculate_totals(prices: list[Decimal], tax_rate: Decimal = Decimal("0.08")) -> dict[str, Decimal]:
    item_total = sum(prices, Decimal("0"))
    tax = (item_total * tax_rate).quantize(CENT, rounding=ROUND_HALF_UP)
    return {"item_total": item_total, "tax": tax, "total": item_total + tax}

def validate_checkout(first: str, last: str, postal: str) -> None:
    for value, label in ((first, "First Name"), (last, "Last Name"), (postal, "Postal Code")):
        if not value.strip():
            raise CheckoutValidationError(f"Error: {label} is required")

assert calculate_totals([Decimal("29.99")])["tax"] == Decimal("2.40")
try:
    validate_checkout("Ada", "", "12345")
except CheckoutValidationError as e:

def _deep_merge(base: dict, overrides: dict) -> dict:
    for key, value in overrides.items():
        if isinstance(value, dict) and isinstance(base.get(key), dict):
            _deep_merge(base[key], value)
        else:
            base[key] = value
    return base

    unknown = set(overrides) - set(payload)

        raise PayloadError(f"Unknown booking fields: {sorted(unknown)}")
    try:
        return _deep_merge(payload, overrides)
    except TypeError as e:
        raise PayloadError("Invalid override value") from e

                    if attempt == times:
                        raise
                    log.warning("%s failed (%s), retry %d/%d in %.1fs", func.__name__, e, attempt, times, wait)
                    time.sleep(wait)          # sleep is fine HERE: it's backoff, not a test wait
                    wait *= backoff
        return wrapper
    return decorator

import logging, time
from collections.abc import Callable, Iterator
from contextlib import contextmanager
from typing import TypeVar

T = TypeVar("T")
log = logging.getLogger(__name__)

def wait_until(condition: Callable[[], T], timeout: float = 10, interval: float = 0.25, message: str = "") -> T:
    deadline = time.monotonic() + timeout            # monotonic: immune to clock changes
    last: T | None = None
    while time.monotonic() < deadline:
        last = condition()
        if last:
            return last
        time.sleep(interval)
    raise TimeoutError(f"Timed out after {timeout}s: {message or condition!r} (last value: {last!r})")

@contextmanager
def timer(name: str) -> Iterator[None]:
    start = time.perf_counter()
    try:
        yield
    finally:
        log.info("%s: %.2fs", name, time.perf_counter() - start)

from typing import Any

def json_diff(expected: Any, actual: Any, path: str = "$") -> list[str]:
    """Return human-readable differences, e.g. '$.bookingdates.checkin: expected 2026-01-01, got 2026-01-02'."""
    if isinstance(expected, dict) and isinstance(actual, dict):
        diffs = []
        for key in expected.keys() | actual.keys():
            if key not in actual:
                diffs.append(f"{path}.{key}: missing in actual")
            elif key not in expected:
                diffs.append(f"{path}.{key}: unexpected field")
            else:
                diffs += json_diff(expected[key], actual[key], f"{path}.{key}")
        return sorted(diffs)
    if isinstance(expected, list) and isinstance(actual, list):
        if len(expected) != len(actual):
            return [f"{path}: length {len(expected)} != {len(actual)}"]
        return [d for i, (e, a) in enumerate(zip(expected, actual)) for d in json_diff(e, a, f"{path}[{i}]")]
    return [] if expected == actual else [f"{path}: expected {expected!r}, got {actual!r}"]

def longest_unique(s: str) -> int:
    last_seen: dict[str, int] = {}
    start = best = 0
    for i, ch in enumerate(s):
        if last_seen.get(ch, -1) >= start:
            start = last_seen[ch] + 1          # shrink window past the repeat
        last_seen[ch] = i
        best = max(best, i - start + 1)
    return best

    i, j = 0, len(s) - 1
    while i < j:
        if not s[i].isalnum():
            i += 1
        elif not s[j].isalnum():
            j -= 1
        elif s[i].casefold() != s[j].casefold():
            return False
        else:

def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    seen: dict[int, int] = {}                 # value -> index

    return None

deep dive Generators are everywhere in pytest

A yield fixture is a generator: code before yield is setup, and code after is teardown. Understanding generators demystifies fixtures (P03-04). Here is what pytest does with one, by hand:

def browser_fixture():
    print("setup:    launch browser")
    yield "<browser>"                 # the value pytest injects into the test
    print("teardown: close browser")

gen = browser_fixture()
browser = next(gen)                   # pytest runs the fixture up to `yield`...
print("test:     using", browser)
next(gen, None)                       # ...and resumes it after the test -> teardown
deep dive Pagination as a generator

It hides page mechanics from tests. for product in iter_products(...) reads naturally, stops early if the consumer breaks, and never loads 10,000 products into memory.

from collections.abc import Iterator
from typing import Any

PAGES = {1: ["Pliers", "Bolt Cutters"], 2: ["Claw Hammer", "Thor Hammer"], 3: ["Hand Saw"]}

class FakeResponse:
    def __init__(self, body: dict[str, Any]) -> None:
        self.body = body
    def raise_for_status(self) -> None:
        return None
    def json(self) -> dict[str, Any]:
        return self.body

class FakeSession:
    """Stands in for requests.Session: 5 made-up products spread over 3 pages."""
    def get(self, url: str, params: dict[str, int], timeout: float) -> FakeResponse:
        page = params["page"]
        print(f"   [HTTP] GET {url}?page={page}")
        return FakeResponse({"data": PAGES[page], "current_page": page, "last_page": len(PAGES), "total": 5})

def iter_products(session, base_url: str, timeout: float = 10) -> Iterator[Any]:
    page = 1
    while True:
        resp = session.get(f"{base_url}/products", params={"page": page}, timeout=timeout)
        resp.raise_for_status()
        body = resp.json()
        yield from body["data"]
        if body["current_page"] >= body["last_page"]:
            return
        page += 1

print("count:", sum(1 for _ in iter_products(FakeSession(), "http://fake")))        # 3 requests
print("first:", next(p for p in iter_products(FakeSession(), "http://fake") if "Hammer" in p))
# ^ only 2 requests: page 3 is never fetched, because the consumer stopped asking

deep dive The GIL and parallel tests

CPython's Global Interpreter Lock lets only one thread execute Python bytecode at a time. Threads still help for I/O-bound work (HTTP calls release the GIL while waiting), but CPU-bound work needs processes. That's why pytest-xdist uses worker processes (P07). Newer Python versions offer an experimental free-threaded build, but test tooling still assumes processes.

deep dive Circular imports

They usually mean two modules need each other: pages importing api importing pages. Fix it by moving shared types to a leaf module (framework/types.py) or importing inside a function.

Interview Q&A

Answer out loud in under two minutes before you open each one.

HGenerator vs list: when do you use each?
A list holds all items in memory and can be iterated many times, indexed and measured with len. A generator produces items lazily, uses constant memory, can be infinite, and can be consumed only once. Use generators for large or unbounded streams (paginated APIs, log lines, unique data), and lists when you need random access or multiple passes.
HHow does a pytest yield fixture relate to generators?
It is a generator function. pytest calls next() to run setup up to yield (the yielded value is injected into the test), and after the test it resumes the generator to run teardown. That's why teardown runs even if the test fails.
SHProtocol vs ABC?
ABCs use nominal typing (you must inherit), give you shared implementation, and fail at instantiation if methods are missing. Protocols use structural typing (any object with the right methods fits), checked statically by mypy. Protocols suit dependency injection and fakes; ABCs suit families of classes you own.
SHWhat is the GIL and how does it affect parallel test execution?
The GIL lets one thread run Python bytecode at a time per process. I/O-bound work (HTTP, browser I/O) still overlaps because waiting releases the GIL, but CPU-bound work doesn't parallelise with threads. pytest-xdist sidesteps this by running tests in separate processes, each with its own interpreter. That also isolates global state, so session fixtures run once per worker.
SHHow would you share a test framework across 10 repos?
Package it (pyproject + build backend), version it with semver, publish to an internal index (or install from a Git tag), keep a changelog, and give it its own CI with unit tests. Keep the core small and stable (config, clients, base page, reporting hooks) and put app-specific pages and clients in each product repo. Deprecate before removing.

Identity, equality and truthiness

== asks "same value?"; is asks "the very same object?". And every object is either truthy or falsy — which is exactly why bool("False") bit you in P02-03.

a = [1, 2]
b = [1, 2]
print(a == b, a is b)                # True False - equal values, two different objects

response = {"error": None, "items": [], "count": 0}
print(response["error"] is None)     # `is None` - the right test for None

for value in (None, 0, "", [], {}, "False", [0]):
    print(f"{value!r:>8} -> {bool(value)}")
# `if not items:` can't tell "missing" from "empty" - assert the exact value you expect
Z== vs is?
== compares values (it calls __eq__); is compares identity — whether two names point at the very same object. Use is only for singletons: None, True, False. Two equal lists are == but not is.
02

Scope, closures and late binding

Python looks a name up in four places, in order: Local, Enclosing function, Global (module), Built-in. Closures (P02-05) capture the variable, not its value — which bites when you build checks or callbacks in a loop.

checks = [lambda: f"check {i}" for i in range(3)]
print([c() for c in checks])            # ['check 2', 'check 2', 'check 2']   <- late binding

checks = [lambda i=i: f"check {i}" for i in range(3)]     # bind the value NOW
print([c() for c in checks])            # ['check 0', 'check 1', 'check 2']

def make_counter():
    count = 0
    def bump() -> int:
        nonlocal count                  # without this, `count += 1` raises UnboundLocalError
        count += 1
        return count
    return bump

attempt = make_counter()
print(attempt(), attempt(), attempt())  # 1 2 3 - the closure remembers `count`
HWhy do all my lambdas return the loop's last value?
A closure looks its variable up when the function is called, not when it is defined (late binding). After the loop the variable holds its last value, so every lambda sees that. Bind the value at definition time with a default argument (lambda i=i: ...) or functools.partial.

import re

line = "2026-01-05 10:00:02 ERROR payment: card declined (order=17, amount=29.99)"

Dates and times

Drill 19 validates booking dates, and Restful-Booker payloads carry them. Parse to real date objects before comparing — and keep timestamps timezone-aware, because your laptop and the CI runner are rarely in the same zone.

from datetime import date, datetime, timedelta, timezone

checkin = date.fromisoformat("2026-01-01")
checkout = checkin + timedelta(days=4)
print(checkout.isoformat(), (checkout - checkin).days)            # 2026-01-05 4

stamp = datetime.strptime("05/01/2026 14:30", "%d/%m/%Y %H:%M")   # parse a UI date format
print(stamp.strftime("%Y-%m-%dT%H:%M"))                           # 2026-01-05T14:30

created = datetime(2026, 1, 5, 23, 30, tzinfo=timezone.utc)
ist = timezone(timedelta(hours=5, minutes=30))
print(created.date(), "->", created.astimezone(ist).date())       # same instant, different DAY

now = datetime.now(timezone.utc)          # timezone-aware; a naive datetime.now() depends on the machine
print(now.tzinfo)
HNaive vs aware datetimes — why does it matter in tests?
A naive datetime has no tzinfo: it means "whatever this machine's local time is", so the same test can pass on a laptop and fail on a CI runner in UTC. An aware datetime carries its offset. Create timestamps with datetime.now(timezone.utc), compare aware with aware, and convert only for display. (datetime.utcnow() returns a naive value and is deprecated since Python 3.12.)

The __main__ guard

P02 tells you to put your asserts under if __name__ == "__main__": — here is why. Run a file directly and Python names it "__main__"; import it and the name is the module's own. The guard keeps self-checks from running when P03's tests import your functions.

def total(prices: list[int]) -> int:
    return sum(prices)

print("module name:", __name__)

if __name__ == "__main__":          # True when the file is run directly, False when it is imported
    assert total([1, 2]) == 3
    assert total([]) == 0
    print("self-checks passed")
ZWhat does if __name__ == "__main__": do?
It runs the block only when the file is executed directly, not when it is imported. That lets one file be both a reusable module and a script with its own self-checks or command-line entry point.

The exception family tree

P02-02 says "never bare except:". The reason is the hierarchy: KeyboardInterrupt and SystemExit sit under BaseException, outside Exception. Note also that ConnectionError and TimeoutError are both kinds of OSError — useful when you choose what @retry should catch.

print(KeyboardInterrupt.__mro__[1].__name__, "<-", "KeyboardInterrupt")   # BaseException
print(KeyError.__mro__[1].__name__, "<-", "KeyError")                     # LookupError
print(issubclass(ConnectionError, OSError), issubclass(TimeoutError, OSError))   # True True

class FrameworkError(Exception):
    """Base class: callers can catch everything the framework raises."""

class ApiError(FrameworkError):
    def __init__(self, status: int, body: str) -> None:
        super().__init__(f"API returned {status}: {body}")
        self.status = status

try:
    try:

A bare except: catches BaseException, which includes KeyboardInterrupt and SystemExit — so Ctrl-C stops working and real bugs are swallowed. except Exception leaves those alone; catching the specific class is better still. Money through JSON

P02-01 says "money is not a float" — but json.loads turns every decimal number into one. Ask it for Decimals instead; requests passes the same argument through: resp.json(parse_float=Decimal).

import json
from decimal import Decimal

body = '{"name": "Backpack", "price": 0.1, "tax": 0.2}'

as_float = json.loads(body)
print(as_float["price"] + as_float["tax"])              # 0.30000000000000004

as_decimal = json.loads(body, parse_float=Decimal)      # keep money exact straight off the wire
print(as_decimal["price"] + as_decimal["tax"])          # 0.3

try:
    json.dumps(as_decimal)
except TypeError as e:
    print("TypeError:", e)                              # Decimal is not JSON serializable
print(json.dumps(as_decimal, default=str))              # the same trick save_json() uses
HHow do you keep prices exact when an API returns JSON numbers?
Parse with parse_float=Decimal (or a pydantic model with Decimal fields) so the value never becomes a float. When writing JSON, serialise Decimals as strings with default=str.

async / await in one screen

This learning path uses Playwright's sync API (it matches pytest-playwright), but you will be asked about the async one. async code runs many waits on one thread: await hands control back while I/O is pending. This example has no Run button — asyncio.run() needs an ordinary Python process, so try it in your terminal.

import asyncio, time

async def fetch(name: str, seconds: float) -> str:
    await asyncio.sleep(seconds)          # hands control back while "waiting on I/O"
    return f"{name} done"

async def main() -> None:
    start = time.perf_counter()
    results = await asyncio.gather(fetch("users", 0.2), fetch("products", 0.2), fetch("cart", 0.2))
    print(results, f"in {time.perf_counter() - start:.1f}s")    # ~0.2s, not 0.6s

asyncio.run(main())
HSync vs async Playwright — which and why?
Both drive the same browser. The sync API reads top to bottom and fits pytest-playwright's fixtures. The async API uses async/await and suits code that already runs in an event loop or juggles many concurrent I/O tasks. Don't mix them: the sync API refuses to run inside a running event loop.
